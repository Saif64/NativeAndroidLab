## Think in three layers

### 1. Project layer: `NativeAndroidLab/`

This is the whole Gradle project. It may contain one app or many modules.

| File | Responsibility |
|---|---|
| `settings.gradle.kts` | Names the project, declares repositories, and includes modules such as `:app`. |
| `build.gradle.kts` | Top-level build configuration. In this project it declares plugins that modules may use. |
| `gradle.properties` | Gradle and Android build flags. It affects the build process, not app behavior. |
| `gradlew` | macOS/Linux Gradle wrapper command. It makes the project use its pinned Gradle version. |
| `gradlew.bat` | The same wrapper for Windows. |
| `gradle/wrapper/gradle-wrapper.properties` | Pins the Gradle distribution version and download URL. |
| `gradle/libs.versions.toml` | Version catalog: central names and versions for plugins and libraries. |
| `local.properties` | This Mac's Android SDK path. Machine-specific; do not commit or hand-edit it casually. |

Important distinction: **Gradle builds the app; Android runs the app.**

### 2. Module layer: `app/`

`app` is one Android application module. A larger project can also contain library
modules such as `:core`, `:data`, or `:feature:home`. We have only `:app` now.

`app/build.gradle.kts` is the module's build contract. Open it and locate:

- `namespace`: package used for generated Android code.
- `applicationId`: identity installed on the device and used by the Play Store.
- `minSdk`: oldest supported Android API.
- `targetSdk`: behavior level the app targets.
- `compileSdk`: Android APIs available while compiling.
- `dependencies`: libraries this module can use.

Do not change any of these today. Just find them.

### 3. Source-set layer: `app/src/`

A source set is a version of code/resources built for a purpose.

| Folder | Responsibility |
|---|---|
| `src/main` | Production app code and resources. This ships in the APK/AAB. |
| `src/test` | Local JVM tests. Usually fast and do not need an emulator. |
| `src/androidTest` | Instrumented tests that run on an Android device/emulator. |

Inside `src/main`:

| Path | Responsibility |
|---|---|
| `AndroidManifest.xml` | Declares Android components, permissions, app theme, launcher activity, and platform metadata. |
| `java/.../MainActivity.kt` | Kotlin source. `MainActivity` is the Android component that currently hosts the Compose UI. |
| `java/.../ui/theme/` | Compose colors, typography, and Material theme setup generated by the template. |
| `res/values/strings.xml` | String resources such as the app name. Later this enables localization. |
| `res/values/colors.xml` | Named Android color resources. |
| `res/values/themes.xml` | Android window/activity theme used before and around Compose. |
| `res/drawable/` | XML or bitmap drawables. |
| `res/mipmap-*/` | Launcher icons at different device pixel densities. |
| `res/xml/` | Structured platform configuration, currently backup/data-extraction rules. |
| `keepRules/rules.keep` | Rules for preserving code/resources when release optimization removes or renames them. |

Why is Kotlin under a folder named `java`? Android historically used Java. Gradle
allows both Java and Kotlin sources there, so the old folder name remains common.

## Flutter → Android mapping

| Flutter project | This native Android project |
|---|---|
| `android/app/build.gradle` | `app/build.gradle.kts` |
| `android/app/src/main/AndroidManifest.xml` | `app/src/main/AndroidManifest.xml` |
| `android/app/src/main/kotlin/.../MainActivity.kt` | `app/src/main/java/.../MainActivity.kt` |
| `lib/main.dart` | No exact equivalent. `MainActivity.setContent { ... }` is the current UI entry boundary. |
| `assets/` plus platform resources | Mostly `app/src/main/res/`, though Android resources are compiled and typed. |
| `test/` | `app/src/test/` for local tests; `androidTest/` for device tests. |
| `pubspec.yaml` dependencies | Gradle dependencies, commonly named through `libs.versions.toml`. |

## Generated folders: recognize, then ignore

- `.gradle/`: Gradle cache and task state.
- `app/build/`: compiled classes, APKs, reports, and other build output.
- `.idea/`: Android Studio project settings.

Do not learn the project by reading generated output. Start from `settings.gradle.kts`,
`app/build.gradle.kts`, `AndroidManifest.xml`, `MainActivity.kt`, and `res/values`.
